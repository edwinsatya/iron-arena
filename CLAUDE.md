# IRON ARENA — browser 2D side-view fantasy brawler, 1v1 online with rollback netcode

(Packages are `@iron-arena/*`; the lobby is the Cloudflare Worker `iron-arena-lobby`.)

Game design: docs/GAME.md (current). Architecture and netcode: docs/PLAN.md (§2 game design there is the old fighter, superseded by GAME.md).

## Layout
- packages/sim — deterministic game logic (pure TS, zero runtime deps). Rules: .claude/rules/sim-determinism.md
  - data/heroes — Benika, Lysa, Hyōga, Hyōshin, Akari, Reo, Kage, Homura, Gōkai, Yomi, Kuma, Karasu, Kamakiri, Kurage, training dummy (actions: strikes, projectiles, areas, skills, ultimates, grabs)
  - side view: everything lives on z = 0 (step() flattens); input is left/right + jump
- packages/netcode — rollback session (GGPO-style), binary input packets, links: loopback, WebRTC, WebSocket relay
- packages/shared — input bits, lobby/control protocol (zod), constants (title, roster ids, stages)
- apps/web — Next.js app; game code in src/game (loop, input, render2d, hud, audio), UI in src/ui, online code in src/net
  - app/globals.css — the design system, "the dusk tournament": iron plaques with gold corner brackets (choose), parchment (read), gules/azure heraldry for P1/P2; Grenze + Alegreya Sans, kana in Shippori Mincho B1. The UI is vector; only heroes and arenas are pixel art
  - render2d/ — canvas 2D renderer: stage2d (painted parallax), sprites (atlas, state → frame), effects2d
  - hud/ — the fight HUD and touchPad.ts (phone controls; writes input/touch.ts). `.game-view` is a size container: in-game CSS uses @container / cqw / cqh, never the window, because a phone held upright shows the match rotated 90° (SIDEWAYS_QUERY)
  - looks.ts — per-hero colours, sound family, sprite animation per action (render-only)
  - portraits.ts — HUD / select / skill-card pictures from the pack art (or drawn from sprites)
  - public/sprites/<hero> — generated by `pnpm sprites [hero…]` from assets-src/sprites/*.zip (elie automata packs, never commit the zips); missing moves can be built from a pack's own frames (pick, other facings, plague recolour, tilts — docs/CHARACTERS.md)
- apps/lobby — room logic shared by a Cloudflare Worker + Durable Object (prod) and a Node server (dev)
- tools — synctest, soak, balance, replay, lobby-smoke, sprites CLIs

## Commands
pnpm dev · pnpm test · pnpm synctest · pnpm soak · pnpm balance · pnpm sprites · pnpm e2e · pnpm typecheck · pnpm lint · pnpm build

## Rules
- Rendering, audio and HUD only READ GameState. Nothing outside packages/sim mutates it.
- Gameplay numbers (damage, frames, hitboxes, cooldowns, movement) live in packages/sim/data and src/constants.ts, never in render code.
- After any sim change: pnpm test and pnpm synctest must pass before you say it's done; run pnpm balance after number changes.
- After any netcode change: pnpm soak must report 0 mismatches.
- GameState is plain data; cloneState() and checksum() walk it generically, so new fields are covered automatically — keep them integers.
- Pin exact dependency versions.
- Sprite packs are licensed for use inside the game only: credit "elie automata" (and the Void Mantis pack for Kamakiri, see CREDITS.md), keep raw packs out of git.
- Player-facing text is English. Hero and skill names may use romanized Japanese words (Chiwari Shatter, Kōbō Aegis); decorative kana are fine.
- Original IP only: no names, characters, art, music or audio from existing games.
